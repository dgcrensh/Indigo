# Scaffold (milestone 0)

How milestone 0 of the [v1 roadmap](../v1-roadmap.md) is built. Builds on nothing.

**Status:** shipped

## Goal

Afterwards you can clone the repo, run one script, and get the core tests and the app build checked, and you
can launch an empty Interface Describer window on the Mac. Every later plan has a place to put code and a
check that tells it whether it worked.

## Scope

**In:**

- `CLAUDE.md` with the repo's conventions for agents.
- The `DescriberCore` Swift package with one placeholder type and one test.
- The app target, generated by XcodeGen, that launches an empty document window.
- The `.uidesc` document type declared as a package.
- `scripts/check.sh` and a GitHub Actions workflow that runs it on a macOS runner.
- A `swift-format` configuration and a format check.

**Out:**

- The data model and file format (milestone 1). The placeholder type is deleted there.
- `NSDocument` reading and writing (milestone 3). Here the document class has empty read and write methods.
- Any canvas, panel, or sidebar UI (milestones 3 to 6).
- Signing, notarization, and distribution (spec Section 14, never in v1).
- A Linux CI job for the core. The core stays Foundation-only so one can be added later, but v1 CI is macOS only.

## Steps

| # | Step | Touches | Depends on |
| --- | --- | --- | --- |
| 1 | Core package | `Packages/DescriberCore/…` | none |
| 2 | App target and document type | `project.yml`, `InterfaceDescriber/…`, `.gitignore` | none |
| 3 | Check script and formatting | `scripts/check.sh`, `.swift-format` | 1, 2 |
| 4 | CI workflow | `.github/workflows/ci.yml` | 3 |
| 5 | `CLAUDE.md` and README | `CLAUDE.md`, `README.md` | 3 |

1. **Core package.** `Packages/DescriberCore/Package.swift` with one library product `DescriberCore`, Swift 5.10
   tools, platforms `.macOS(.v14)`. One source file, `DescriberCore.swift`, declaring
   `public enum DescriberCore { public static let schemaVersion = 1 }`. One test in `DescriberCoreTests`
   asserting `schemaVersion == 1`. The package imports Foundation only.
2. **App target and document type.** `project.yml` defines the `InterfaceDescriber` macOS app (deployment
   target 14.0) depending on the local `DescriberCore` package, and an `InterfaceDescriberTests` unit-test
   target. `InterfaceDescriber/` holds `AppDelegate.swift`, a `Document` subclass of `NSDocument` whose
   `read(from:ofType:)` and `fileWrapper(ofType:)` are empty stubs, and `Info.plist` declaring the exported UTI
   `com.dgcrensh.interface-describer.project` conforming to `com.apple.package`, extension `uidesc`, role Editor.
   The app name and extension come from one `AppIdentity` enum (decision D5 in the roadmap). `.gitignore` adds
   `*.xcodeproj`, `.build/`, `DerivedData/`, and `*.uidesc/.editor-state.json`. One app test asserts that
   `Document.readableTypes` contains the UTI.
3. **Check script and formatting.** `scripts/check.sh` runs, in order and stopping at the first failure:
   `swift test` in the core package; `swift format lint --strict --recursive` over `Packages/` and
   `InterfaceDescriber/`; `xcodegen generate`; `xcodebuild test` for the app scheme on `platform=macOS`. Each
   stage prints its name. Flags `--core` (first two stages only) and `--no-app` (alias) let a session without
   Xcode run what it can. `.swift-format` sets 4-space indentation and a 120-column line length.
4. **CI workflow.** `.github/workflows/ci.yml` runs on pushes and pull requests to `main` on `macos-14`, installs
   XcodeGen with Homebrew, and runs `scripts/check.sh`. One job named `check`.
5. **`CLAUDE.md` and README.** `CLAUDE.md` states the conventions later plans rely on: logic and rules go in
   `DescriberCore` with tests, and the app stays a thin layer; every edit goes through a command (from
   milestone 2); `scripts/check.sh` must pass before a PR is ready; the example project in `Schema/examples/`
   must re-save byte for byte (from milestone 1); a plan's **Status** line is updated in the PR that ships it;
   plans follow plan, review, build. `README.md` gets a short description, how to run `scripts/check.sh`, and a
   link to the roadmap.

## Done when

**Tests and CI:**

- [ ] `DescriberCoreTests` has a passing test for `DescriberCore.schemaVersion == 1`.
- [ ] `InterfaceDescriberTests` has a passing test that the document type declares the `.uidesc` UTI.
- [ ] `scripts/check.sh` passes locally and the `check` job is green on this PR.
- [ ] `scripts/check.sh --core` runs only the core stages.
- [ ] No `.xcodeproj` is committed.

**On the Mac:**

- [ ] `xcodegen generate` then opening the project and running shows a new, empty untitled window.
- [ ] File > New opens another empty window.
- [ ] In Finder, a folder renamed to end in `.uidesc` shows as a single document with the app's document icon
  after the app has run once.
