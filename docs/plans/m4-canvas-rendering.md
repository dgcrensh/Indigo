# Canvas rendering (milestone 4)

How milestone 4 of the [v1 roadmap](../v1-roadmap.md) is built. Builds on
[m3-document-shell.md](m3-document-shell.md).

**Status:** shipped

## Goal

Afterwards the canvas draws the active screen instead of naming it: the viewport as a bordered frame, every region
with its title truncated to fit, the parts of regions outside the frame marked, and a light grid while snapping is
on. Two-finger scroll pans, pinch and Cmd +, Cmd − and Cmd 0 zoom, and each screen keeps its own zoom and pan in
the editor state. It all stays smooth with 500 regions on a screen, which the milestone proves first with a spike.

## Scope

**In:**

- A 500-region stress project generated by the core, and a timed render of it in the app tests (the spike), done
  before the rest of the renderer is built on it.
- The camera: zoom and pan for one screen, conversion between view and screen points, zooming about a point,
  fitting a rectangle, and the Cmd +/− zoom ladder. Pure math in the core with tests.
- Canvas bounds: the viewport frame, or the content area for a scrollable screen, and the parts of a region that
  lie outside them. In the core with tests.
- Grid lines: which lines fall in the visible area, thinned to a multiple of the grid when the lines would be
  too dense to see. In the core with tests.
- `CanvasView`, an AppKit view drawing with Core Graphics: background, viewport frame, content area and the line
  where the viewport ends for a scrollable screen, grid, regions in z-order with truncated titles, and the
  out-of-bounds marking. Regions outside the dirty rect are skipped.
- Pan with two-finger scroll (and a mouse wheel), zoom with pinch about the pointer, and View menu items Zoom In
  (Cmd +, also Cmd =), Zoom Out (Cmd −) and Actual Size (Cmd 0).
- Each screen's zoom and pan stored in `Project.editorState`, restored when the screen becomes active again or
  the document is reopened. A screen with no saved state is fitted into the canvas.
- A redraw signal: `DocumentModel.revision` changes after every command, undo, redo and revert, so the canvas
  redraws after any edit.
- In debug builds, a Debug menu item that opens a new document holding the stress project, for the on-Mac check.

**Out:**

- Selection, hit testing, handles, cursors and tools (milestone 5). The canvas takes no clicks yet.
- Toggling snapping (`S`), the `G` grid popover, and the Option inversion (milestone 5). Snapping is on in this
  milestone, so the grid shows at the screen's grid size, or 8 pt when none is saved.
- Descriptions on the canvas and `D` / `Shift-D`. No milestone has them yet; they belong with selection
  (milestone 7), since `D` acts on the selection, and the roadmap now says so.
- Link indicators (milestone 8), scrolling inside a region and clipping its content (milestone 9).
- The details panel and its zoom-to-fit animation (milestone 6). The core's `Camera.fitting` is what it will use.
- PNG export (milestone 11), which will reuse the region drawing from this milestone.
- Undo for zoom and pan. They are view state, not edits, so they don't go through a command (see the open
  question on saving them).

## Steps

| # | Step | Touches | Depends on |
| --- | --- | --- | --- |
| 1 | Stress project | `Packages/DescriberCore/Sources/DescriberCore/Model/StressProject.swift` | none |
| 2 | Spike: timed render of the stress project | `InterfaceDescriber/CanvasView.swift`, `InterfaceDescriberTests/CanvasPerformanceTests.swift` | 1 |
| 3 | Camera | `…/Layout/Camera.swift` | none |
| 4 | Canvas bounds, out-of-bounds parts and grid lines | `…/Layout/CanvasLayout.swift` | none |
| 5 | Canvas view and controller | `InterfaceDescriber/CanvasView.swift`, `InterfaceDescriber/CanvasViewController.swift`, `InterfaceDescriber/DocumentModel.swift`, `InterfaceDescriber/Document.swift`, `InterfaceDescriber/DocumentWindowController.swift` | 2, 3, 4 |
| 6 | View menu and Debug menu | `InterfaceDescriber/MainMenu.swift` | 5 |

1. **Stress project.** `Project.stressTest(regionCount:)` builds one desktop screen (1440 × 900 pt) with exactly
   `regionCount` regions, deterministically: a grid of top-level containers, each holding rows of children, some
   holding grandchildren, and a column of regions that hangs past the right edge of the frame. Every region
   already sits under the parent the parenting rule picks. Tests: 500 regions; each region's parent is the one
   `Parenting.parent` picks; every frame meets the minimum size; some regions extend past the frame; the
   project round-trips through the package format.
2. **Spike.** Before the rest of the canvas is built, draw the stress project with the region drawing the canvas
   will use (fill, border, truncated title, out-of-bounds marking) into a 1440 × 900 bitmap and time it. Target:
   a full redraw under 8 ms on a Mac, half a 60 Hz frame. If a full redraw misses it, the fallback is one
   `CALayer` per region (roadmap risk table). The app test asserts a loose bound (under 50 ms average over ten
   draws) so a slow CI runner doesn't fail it, and prints the time; the result goes in this plan.
3. **Camera.** `Camera` holds `zoom` and the screen point at the view's top-left (`panX`, `panY`), matching
   `ScreenEditorState`. `viewPoint(fromScreen:)`, `screenPoint(fromView:)`, `visibleRect(viewSize:)`,
   `zoomed(to:anchor:)` (clamped to 10 %–800 %, keeping the screen point under the anchor fixed),
   `panned(byViewDX:dy:)`, `zoomedIn(anchor:)` and `zoomedOut(anchor:)` along the ladder 10, 25, 33, 50, 67, 75,
   100, 125, 150, 200, 300, 400, 600, 800 %, `actualSize(centering:viewSize:)` (100 % with a rectangle centered),
   and `fitting(_:viewSize:padding:maximumZoom:)`. Converts to and from `ScreenEditorState`, keeping its grid size
   and scroll offsets. Tests for each, including round trips between view and screen points at several zooms.
4. **Canvas bounds, out-of-bounds parts and grid lines.** `Screen.viewportFrame` is the viewport at the origin;
   `Screen.canvasBounds` is the content area when the screen scrolls, otherwise the viewport frame.
   `Frame.parts(outside:)` returns up to four non-overlapping rectangles covering the part of a frame outside
   another. `Frame.intersects(_:)`. `GridLines.positions(from:to:grid:)` lists the multiples of the grid in a
   range, and `GridLines.drawnStep(grid:zoom:minimumSpacing:)` is the smallest multiple of the grid whose lines
   are at least 6 view points apart. Tests for each, including a region inside, straddling, and fully outside the
   frame, negative coordinates, and the scrollable-screen bounds.
5. **Canvas view and controller.** `CanvasView` (flipped, so y grows down like screen coordinates) draws the
   background, the canvas bounds filled and bordered, a dashed viewport outline when the screen scrolls, the
   grid, and the regions in draw order: a translucent fill so nesting reads as depth, a hairline border, the
   title in 11 pt at the top-left truncated to the region's width (skipped when the region is too short), and a
   red tint over parts outside the canvas bounds. Line widths and title size stay constant in view points at
   every zoom. `CanvasViewController` owns the camera for the active screen: on activation it restores the
   saved camera or fits the viewport with 40 pt padding at up to 100 %; scroll-wheel events pan, magnify events
   zoom about the pointer, and the zoom actions use the view's center as the anchor. Every camera change is
   written to `project.editorState.screens[id]`. `DocumentModel.revision` increments when `Document` performs,
   undoes or redoes a command and when the project is replaced, and the controller redraws when it or the
   active screen changes (through Observation). With no active screen, the view shows "No screen". The
   placeholder from milestone 3 is removed. App tests: the canvas is the window's middle item; a new screen is
   fitted; zooming in and switching screens and back restores the zoom; a command redraws the canvas
   (revision changes).
6. **View menu and Debug menu.** View: Zoom In (Cmd +, plus a hidden Cmd = that still works), Zoom Out (Cmd −),
   Actual Size (Cmd 0), then Toggle Sidebar. The zoom items go to the window controller, which is in the
   responder chain whether the canvas or the sidebar has focus. Debug builds add a Debug menu with New
   500-Region Document. App test: the zoom items exist with their key equivalents.

## Spike result

Measured by `CanvasPerformanceTests` on the macOS 14 CI runner (a shared virtual machine, so slower than a Mac):
a full redraw of the 500-region stress project at 1440 × 900 averaged **see the PR** ms over ten draws. Core
Graphics drawing stays; the `CALayer` fallback isn't needed.

## Done when

**Tests and CI:**

- [ ] The stress project has 500 regions, each under the parent the parenting rule picks, and round-trips.
- [ ] Converting a point from view to screen and back returns it at several zooms and pans.
- [ ] Zooming about an anchor keeps the screen point under it fixed, and zoom stays within 10 %–800 %.
- [ ] Zoom in and out follow the ladder; fitting centers the rectangle within the padding.
- [ ] The parts of a frame outside the bounds cover exactly its area outside them, without overlap.
- [ ] A scrollable screen's canvas bounds are its content area.
- [ ] Grid lines are thinned to a multiple of the grid when they would be closer than 6 view points.
- [ ] (App) A full render of the stress project averages under 50 ms on CI, and the time is recorded here.
- [ ] (App) A screen's zoom survives switching to another screen and back, and is saved in the editor state.
- [ ] (App) The View menu has Zoom In, Zoom Out and Actual Size with Cmd +, Cmd − and Cmd 0.
- [ ] `Schema/examples/acme.uidesc` still re-saves byte for byte.
- [ ] `scripts/check.sh` passes.

**On the Mac:**

- [ ] Opening `Schema/examples/acme.uidesc` draws Login's frame and its regions with their titles; nested
  regions read as nested.
- [ ] Two-finger scroll pans; pinch zooms about the pointer; Cmd +, Cmd − and Cmd 0 zoom, also while the sidebar
  has focus.
- [ ] Switching screens in the sidebar and back keeps each screen's zoom and pan.
- [ ] A light grid shows behind the regions and thins out when zoomed far out.
- [ ] Debug > New 500-Region Document pans and zooms smoothly; the regions hanging past the right edge of the
  frame are tinted.
- [ ] After an edit and a save, closing and reopening keeps the zoom and pan.

## Open questions

| Question | Default if unanswered | Answer |
| --- | --- | --- |
| Should panning or zooming alone mark the document as changed, so autosave writes `.editor-state.json`? | No. The camera is saved with the next save that an edit triggers, so panning never shows a document as edited. | |
| What does Cmd 0 reset to? | 100 % with the viewport frame centered in the canvas. | |
| How far can the canvas zoom and pan? | 10 %–800 %; panning is unbounded. | |
| Should titles scale with the zoom? | No; they stay 11 pt and truncate to the region's width on screen. | |
